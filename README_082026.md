# STAR × FM4NPP: corrected linear-probe transfer result (August 2026)

Standalone report on one specific test in this repo. For the full repo picture
(setup, all scripts, full history) see [README.md](README.md); this document
covers just what was tested this round, how, what came out, and how much to
trust it.

## What was tested

Does the pretrained [FM4NPP](https://github.com/FM4NPP/PP_collision) Mamba
backbone — trained only on simulated **sPHENIX** TPC collisions — carry any
representational structure that transfers to **STAR** TPC data, a physically
different detector FM4NPP has never seen?

This is the second attempt at answering that question in this repo. The first
attempt (below, kept for contrast) found nothing. Reading the FM4NPP paper
(2508.14087v1) closely against its own code surfaced two reasons that first
attempt was the wrong test to run, and this round fixes both.

## Round 1 (earlier, flawed methodology) — for contrast

`extract_embeddings_pca.py` fed STAR hits through the frozen pretrained
backbone and a randomly initialized control of the same architecture,
r-sorting points by radius as a stand-in for FM4NPP's real point ordering, and
measured how well the **raw** output embeddings separated hits by true track
ID (silhouette score) on 100 STAR events.

![Earlier probe: silhouette score distribution](silhouette_summary.png)
![Earlier probe: per-event PCA projections, pretrained vs random-init](embeddings_pca.png)

Result: mean silhouette ≈0.20 (pretrained) vs ≈0.19 (random-init), delta
≈+0.007, not significant — the per-event delta histogram straddles zero.
Same null result under both STAR-derived and original sPHENIX normalization
constants. Read at face value: **no evidence of transfer**.

Two problems with that conclusion, found by reading the paper's appendix
directly:

1. **The paper's own Figure 8 shows raw frozen embeddings don't separate by
   track even in-distribution**, on the model's native sPHENIX data — clear
   separation only appears after training a single linear projection on top.
   Round 1 measured exactly the representation the paper itself says isn't
   expected to cluster, regardless of domain transfer.
2. **The real point ordering was never reconstructed.** FM4NPP's actual
   training-time serialization ("Hierarchical Raster Scan") groups points into
   a voxel grid before feeding them to the (order-sensitive, Mamba-based)
   model, using bin-edge statistics that were never published alongside the
   checkpoint. Round 1 substituted plain r-sorting, a real but different code
   path.

Given both, the round 1 null result doesn't actually tell you whether the
pretrained weights carry transferable structure — it mostly tells you that
raw embeddings under the wrong point order don't cluster, which the paper
already predicts regardless of transfer.

## Round 2 (this test): fixing both gaps

### Fix 1 — real point ordering (`star_voxelizer.py`)

FM4NPP's real serialization is implemented by
`fm4npp.datasets.voxelizer.Voxelizer`, which needs precomputed eta/phi/radius
bin edges (normally loaded from a `.pkl` file) to assign each point to a voxel
group, then orders points by (group, radius). `star_voxelizer.py`
reconstructs a working `Voxelizer` for STAR without that file:

- **Eta/phi bins**: quantile ("equal-count") binning computed directly from
  STAR data — identical algorithm to the original, no sPHENIX-specific
  constants involved.
- **Radius bins**: the original hardcodes sPHENIX's own layer-group
  thresholds (40cm/57cm, reflecting its 3-group layer structure). STAR's TPC
  has a different physical layout, so this module instead detects the
  inner/outer sector density valley empirically
  (`detect_radial_groups`, via smoothed-histogram local-minima detection) and
  quantile-bins radius within each group.
- The resulting `final_bins` dict is used to construct a real `Voxelizer`
  instance (bypassing its file-loading `__init__`), whose `tokenize()`/
  `grouping()` methods then give the correct per-point traversal order —
  `hierarchical_raster_scan_order()` sorts points by `(group_id, r)` to
  reproduce it.

### Fix 2 — a trained linear probe, not raw embeddings (`extract_embeddings_linear_probe.py`)

Per the paper's own Figure 8 finding, a single linear layer is trained on top
of the frozen backbone's last-layer embeddings, using a triplet-loss
metric-learning objective (pull same-track embeddings together, push
different-track ones apart) — trained on STAR **training** events, then
evaluated by silhouette score on separate, held-out STAR **test** events.
Done identically for the pretrained backbone and a random-init control, so
the comparison isolates the effect of pretraining.

This is a simplification of the paper's real downstream adapter (a
transformer-decoder instance-segmentation head trained with Hungarian
matching + Dice/Focal/classification losses) — see
[How much to trust this](#how-much-to-trust-this) below.

### Reproducing this

```bash
python extract_embeddings_linear_probe.py \
    --data-dir data/star_fm4npp_2k \
    --checkpoint checkpoints/pp_nerf_m3_k30.ckpt \
    --n-fit-events 60 --n-train-events 300 --n-test-events 100 \
    --norm star --probe-epochs 30 \
    --out linear_probe_summary.png
```

Events are drawn from converted STAR data (see [README.md](README.md) for
the conversion step) and split three ways with no event reused across roles:

- **60 fit events** — used only to fit the Voxelizer's eta/phi/radius bins.
- **300 train events** — used to train the linear probe (triplet loss).
- **100 held-out test events** — used only for the final silhouette
  evaluation reported below; never seen by the probe or the Voxelizer fit.

The whole thing is run twice — once loading the pretrained checkpoint, once
with the same architecture randomly initialized — on the same event splits,
so the only difference between the two runs is whether the backbone started
from pretrained weights.

## Result

| model | mean silhouette (held-out test, n=78) |
|---|---|
| pretrained + linear probe | **0.807 ± 0.129** |
| random-init + linear probe | **0.716 ± 0.130** |

Mean delta (pretrained − random-init): **+0.091 ± 0.059**. Paired Wilcoxon
signed-rank test on the per-event deltas: **p < 0.0001**. (78 of the 100
held-out test events yield a valid silhouette score; the rest have too few
hits or too few distinct tracks for the metric to be defined and are
excluded, same filter used in round 1.)

![Linear-probe silhouette summary: score distributions and per-event delta](linear_probe_summary.png)

The boxplots on the left show the pretrained backbone's post-probe
silhouette scores sitting consistently above the random-init control's; the
histogram on the right shows the per-event delta distribution is shifted
well clear of zero (mean +0.091, most of the mass positive), a clear contrast
with round 1's delta histogram straddling zero.

## How much to trust this

**Accurate framing: statistically significant evidence of transfer, with
caveats — not "proven" or "confirmed."** Three specific things keep this from
being a fully closed case:

- **(a) The Voxelizer's `dim_sweep_order`/`revert_order` parameters are
  unconfirmed assumptions.** Fixing the missing bin-edge `.pkl` file (above)
  doesn't fully pin down the real training-time ordering — these two
  additional parameters are left at the `Voxelizer` class's own defaults
  (`[0,1,2]`/`[0,1,2]`) because the real m3/k30 training config was never
  published, and there's no way to recover the true values without it.
- **(b) The linear probe is a lighter stand-in for the paper's actual
  adapter**, not a reimplementation of it. The paper's real downstream head
  is a transformer-decoder instance-segmentation module trained with
  Hungarian matching plus Dice/Focal/classification losses — considerably
  more capacity and a different training objective than a single linear
  layer with triplet loss. This result shows that transfer exists; it is not
  evidence that STAR would reproduce the paper's own reported ARI/efficiency
  numbers.
- **(c) This is one run with one random-init seed.** Both the pretrained and
  random-init numbers above come from a single run each. A multi-seed
  robustness check — repeating the random-init control (and ideally the
  pretrained run) across several seeds — is the natural next step to confirm
  the +0.091 delta sits outside ordinary run-to-run noise, and hasn't been
  done yet: `extract_embeddings_linear_probe.py` has no `--seed` flag at all
  right now (a prior sweep attempt in the working tree,
  `multiseed_runs/log_seed{2..5}.txt`, failed on exactly that — an
  "unrecognized arguments: --seed N" argparse error), so this needs a small
  script change before it can run, not just repeated invocations.

Put together: this round is a real methodological improvement over round 1,
and the result reverses round 1's conclusion with a statistically significant
margin (p < 0.0001) — genuine evidence that FM4NPP's pretrained weights carry
track-separation structure that transfers to STAR. But it's evidence from one
run, with one still-unconfirmed ordering assumption, measured with a lighter
probe than the paper's real adapter. Treat it as "the pretrained weights
transfer usefully," not as "STAR performance matches the paper."
